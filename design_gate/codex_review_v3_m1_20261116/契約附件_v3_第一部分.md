## 第一部分：對附件 v1、v2 的更正

### A（取代 v1 的 A-2、A-3；A-1、A-4 照舊）Domain Gate

**A-0 正規化（新增）**
1. Unicode NFKC（全形轉半形）。
2. 英文字母轉小寫。
3. 去掉頭尾空白，連續空白縮成一個。
4. 不做繁簡轉換、不做同音字處理、不分詞。
5. 長度以正規化後的 Unicode 字元數計算。

**A-2 規則順序（由上到下，命中就停）**

| 順序 | 規則 | 結果 |
|---|---|---|
| 1 | 長度為 0，或沒有任何中文、英文、數字 | `INVALID_INPUT` |
| 2 | 長度 > 200 | `INPUT_TOO_LONG`：固定回「輸入過長，請拆成短句」。**不截斷、不路由、不處理任何片段**（H-02） |
| 3 | 名詞例外遮罩（A-2a），再切子句（A-2b） | 得到子句與遮罩後文字 |
| 4 | 任何一個子句在**遮罩後**仍命中飛控動詞詞庫，且該子句不是問句 | `FLIGHT_CMD` |
| 5 | 算**領域證據**（A-2c） | `has_domain = true／false` |
| 6 | `has_domain = false` | `OUT_OF_DOMAIN`，固定回「這不在本系統的範圍，或請把問題說完整」 |
| 7 | 句中含「原因、為什麼、為何、怎麼會」 | 固定回「此版本不提供原因分析」，不進 Router（H-25） |
| 8 | 各類意圖關鍵詞打分（權重 1 或 2，字串比對） | scores |
| 9 | 所有意圖類別 0 分 | `QA`（走手冊檢索，查不到就說查不到） |
| 10 | 最高分 ≥ T 且領先第二名 ≥ M | 該類別 |
| 11 | 其他 | `CLARIFY`，列分數最高的 2 類 |

T = 2、M = 1〔待凍結〕。CLARIFY 候選的顯示順序照 v1。

**A-2a 名詞例外遮罩（H-25、R3-F03）**
- 例外表 v1：「返航點、降落點、起飛點」。
- 做法：在整句中由左到右找例外詞（長的優先），把**剛好那幾個字**換成佔位符。其餘文字照常做飛控動詞檢查。
- 例：「顯示返航點後立即返航」。「返航點」被遮罩，後面的「返航」仍命中，結果是 `FLIGHT_CMD`。
- 例：「返航點在哪裡」。遮罩後沒有飛控動詞，繼續往下判。

**A-2b 子句切分**：用「，」「。」「；」「、」「然後」「再」「並」「之後」「後」切。切分只用來判飛控命令，不用來分別執行。

**A-2c 領域證據與意圖分數分開（R3-F03）**
- **領域證據**只來自三個來源：`domains/*.json` 的領域詞、遙測欄位名稱與別名、元件與工具的固定名稱（電量、告警、航線、高度、地圖等，完整詞庫隨程式凍結）。命中至少一個才算 `has_domain = true`。名詞例外詞本身也算領域詞。
- **一般疑問詞不算領域證據**：怎麼、如何、為什麼、哪、多少、幾、什麼、是什麼、是否、能不能、可不可以、會不會、嗎、呢。它們只用來判「是不是問句」，在意圖打分裡權重為 0。
- 所以「今天天氣如何」沒有領域證據，在第 6 條被判成領域外。

**A-3 問句、命令句、混合句**
- 問句、命令句、否定句、「能不能返航」的判定照 v1。
- 混合句：任何一個子句是飛控命令句，整句就是 `FLIGHT_CMD`。
- **話題承接（V3-2）**：v1 不做。沒有領域證據的省略句一律走第 6 條。

**A-5 固定案例（每案只有一個預期結果）**

| 輸入 | 預期 |
|---|---|
| 今天天氣如何 | `OUT_OF_DOMAIN` |
| 如何 | `OUT_OF_DOMAIN` |
| 那現在呢 | `OUT_OF_DOMAIN` |
| 電量現在多少 | `QA` |
| 返航點在哪裡 | `QA` |
| 顯示返航點後立即返航 | `FLIGHT_CMD` |
| 返航，然後告訴我電量 | `FLIGHT_CMD` |
| 不要返航 | `FLIGHT_CMD` |
| 能不能返航 | `QA` |
| 為什麼電量掉這麼快 | 固定回「此版本不提供原因分析」 |
| 201 個字、後半句是「返航」 | `INPUT_TOO_LONG` |

### C（取代 v1 的 C-2 第 1、2 步；其餘照舊）電量斜率

順序改成**先清理、再取視窗**（H-05②）：

1. **清理**（對收到的全部樣本）：
   - `t_i` 不是有限數字：丟掉，計入 `n_dropped`。
   - `t_i` 比現在晚超過 1 秒〔待凍結〕（未來時間戳）：丟掉，計入 `n_dropped`。
   - `soc_i` 不是有限數字，或不在 0～100：丟掉，計入 `n_dropped`。
2. **算亂序比例**（U-04）：照到達順序看，某筆的 `t_i` 小於「之前出現過的最大時間」就算一筆亂序。比例 = 亂序筆數 ÷ 清理後的筆數（去重前）。超過 20%：`INSUFFICIENT`。
3. **排序與去重**：依 `t_i` 排序；時間戳相同只留最後到達的一筆。
4. **取視窗**：`t_end` = 去重後最後一筆的時間；只留 `t_end − W ≤ t_i ≤ t_end`。
5. 之後的充分性、零變異、直線、方向、ETA 照 v1 的第 3～7 步。

新增邊界（H-26）：`reserve_pct` 不是有限數字或不在 0～100 時，斜率與方向照算，但不算 ETA，並記 `reserve_invalid = true`。

### D（取代 v1 的 D-3；補充 D-1、D-2）claim

**D-1 補充（H-05③）**：手冊查不到時用新模板 `T-DOC-NONE`，句型固定是「手冊裡查不到相關內容」。**不可以用 `T-NONE`**，也就是不能說成「沒有告警」。

**D-3 模型選句子的處置（V3-4、R3-F05）**

程式把候選句子分成兩組：

- **必顯示組**（`mandatory_claim_ids`）：`T-PARTIAL`、`T-STALE`、`T-CANNOT`、`T-NOTFOUND`、`T-DOC-NONE`。每個工具最多產生 1 句，一個請求最多 3 個工具，所以最多 3 句。**這組不給模型選，程式固定顯示在答案最前面**，順序是 過期 → 不完整 → 樣本不足 → 查不到。
- **可選組**：其餘句子。模型只從這組選。

上限：整個答案最多 8 句〔待凍結〕。可選組的名額 = 8 − 必顯示組的句數。

| 情況 | 處置 |
|---|---|
| 模型選的 ID 都在可選組內，數量 1 到名額上限 | 必顯示組在前，接著照模型給的順序 |
| 模型選了必顯示組的 ID | 整份退回規則模板 |
| 空集合，且可選組不是空的 | 整份退回規則模板 |
| 可選組本來就是空的 | 不呼叫模型，只顯示必顯示組 |
| 重複 ID | 去重，保留第一次的位置 |
| 超過名額、有不在候選內的 ID、有多餘欄位或自由文字、JSON 壞掉、逾時 | 整份退回規則模板 |

規則模板：必顯示組在前，可選組照固定順序（`T-VALUE` → `T-THRESH` → `T-TREND` → `T-ETA` → `T-COUNT` → `T-NONE` → `T-DOC`）取到名額用完為止。被名額擋掉的可選句記 `claims_truncated = n`，畫面顯示「還有 n 項，見資料表」。必顯示組永遠不會被擋掉。

### E（取代 v1 的 E-1 第 2、3 點；補充 E-3）確認交易

- **交易編號（H-05①）**：提案建立時用作業系統亂數產生 16 bytes 的固定亂數，和提案一起保存。`transaction_id = SHA256(proposal_hash ‖ 亂數)`。**不含時間戳**。同一個提案按兩次確認，編號相同，第二次回傳第一次的結果。
- **提交前複查（H-05④）**：
  - `base_ui_revision`、`workspace_revision` 必須和提案建立時完全相同，否則 DISCARD。
  - 資料部分**只看三件事**：提案引用的資料來源是否變成過期或讀不到、來源身分（哪一趟紀錄、哪個欄位）是否換了、工具狀態是否從可用變成不可用。**數值正常刷新不算變動。**
- **寫磁碟不擋畫面（H-13）**：快照與指標的寫入在 I/O 執行緒做，GUI 與告警不等它。
- **進行中的交易被打斷**：視窗大小改變、或出現安全事件時，

| 交易進度 | 處置 |
|---|---|
| 指標還沒寫完（提交點之前） | DISCARD，原因記 `invalidated`，畫面與指標都是舊版 |
| 指標已寫完、畫面還沒切換 | 用新的視窗大小重新驗證；合格就切換，不合格就走回滾 |
| 回滾目標在新的視窗大小下也不合格 | 見 §N-3 |

### F（取代 v1 的 F-3；補充 F-1、F-4）告警計分

**F-1 補充：共同時鐘（R3-F09）**
- 桌面的 Python 重放器與 Qt 都用作業系統的單調時鐘。兩邊的起點可能不同，所以每次執行開始時做一次對時：重放器送一個帶自己時間的標記，Qt 收到後記自己的時間，來回 5 次取最小來回時間的那一次算偏移。
- 來回時間超過 1 毫秒〔待凍結〕就算對時失敗，**整包標 `ENV_INVALID`，首次結果原樣保留，不換樣本重算**。
- 這個做法能不能達到要求還沒驗證，列入 Ge 前的檢查。

**F-3 事件與異常段配對（R3-F09、H-22）**

1. **事件身分**：`alert_id = (session, 機體, 預測器, 第幾次升起)`。一次告警從「升起」到「解除」算同一個 `alert_id`；中間的「更新」與最後的「解除」都帶同一個編號。
2. **哪些事件可以算偵測成功**：只有**「升起」事件**，而且等級達到該異常段標註的目標等級、預測器與機體相同。「更新」「解除」「合併橫幅」一律不能算。
3. **標註規則**：同一個預測器的兩個異常段，前一段結束到後一段開始不到 5 秒〔待凍結〕的，在標註階段就合併成一段。這在執行前完成，執行後不改標註。所以同一預測器的配對窗不會重疊。
4. **配對**：「升起」事件的來源樣本時間落在某一段的 `[t_onset, t_end + 5 秒]` 內，就屬於那一段。那一段的第一個合格「升起」算命中，其後落在同一段的「升起」算重複，不算誤報，也**不會被拿去配下一段**。
5. 沒落在任何一段的「升起」：誤報。

**F-4 補充**：「有事件但等級沒達到目標」計為失敗（等級不足），另列一欄。

**F-7 固定案例**：升起後更新再解除；同一段內升起兩次；兩段相隔 4 秒與 6 秒；只有解除事件落在下一段；等級低一級的升起；合併橫幅；缺畫格；文字被截斷。每案只有一個分數。

## 第二部分：新增條文

### J：取消、結清與桌面 Ollama 的停止證據（R3-F02、H-01、U-06）

**J-1 「做完」的定義**

每個模型工作有三個各自獨立的旗標，三個都成立才算 DONE、才能把資源名額給下一個工作：

| 旗標 | 意思 |
|---|---|
| `result_disposition` | 結果已經有去處。四選一：`DELIVERED`（已交付）、`DISCARDED_LATE`（太晚到，已丟棄）、`CANCELLED_NO_RESULT`（取消時還沒有輸出）、`FAILED` |
| `stop_evidence` | 有證據顯示後端已經不再運算（J-2） |
| `lease_settled` | 資源帳已歸還 |

- 只有 `DELIVERED` 需要「有完整輸出」。**在載入或讀入提示階段就取消，記 `CANCELLED_NO_RESULT`，照樣可以結清。**
- 回呼函式回來、或 HTTP 連線關閉，都**不算** `stop_evidence`。

**J-2 桌面專用 Ollama 的停止證據**

| 情況 | 證據 |
|---|---|
| 正常完成 | 串流收到 `done: true` 的最後一筆，而且連線已關閉 |
| 取消、逾時、或串流中斷 | 啟動器自己開的那一組程序**全部結束**，而且專用埠已釋放（J-3） |

**J-3 取消流程（V3-1）**

1. 啟動器啟動專用 Ollama 時，把它放進自己建立的程序群組，記下群組編號。專用埠已被占用就停下來，不沿用。
2. 要取消時：關閉連線 → 結束整個程序群組 → 等群組內所有程序結束、埠釋放。等待上限 5 秒〔待凍結〕。
3. 5 秒內確認結束：`stop_evidence` 成立，記 `CANCELLED_NO_RESULT` 或 `DISCARDED_LATE`，結清，重新啟動專用 Ollama。
4. 5 秒內無法確認：**停用桌面模型路徑**，畫面標「模型暫停」，之後的請求全走規則版。不重試、不強制結束群組以外的任何程序。
5. 重新載入模型期間到達的請求走規則版並標「規則」，不排隊等模型。
6. 這只動啟動器自己開的程序。不碰 GCS、不碰系統原本的 Ollama、不改安全設定。

**J-4 其他後端**：LiteRT-LM、llama.cpp 的具體呼叫與完成事件要等拿到固定版本的文件才能寫。寫出來並通過取消演練（G5x）之前，這些後端的模型路徑維持停用。

**J-5 固定案例**：還沒輸出就取消；輸出到一半取消；正常完成後連線沒關；群組內有一個程序沒結束；重啟後舊結果晚到。每一案都不得在三個旗標齊全之前發出下一個名額。

### N：重新啟動與回滾時的版面確認（R3-F10、V3-3）

**N-1 什麼叫「同一個版面」**：元件集合相同、順序相同、每個元件的大小等級相同、分到的列相同、沒有任何元件被刪減、必要元件都放得下。像素尺寸因為螢幕縮放而不同不算改變。

**N-2 啟動流程**
1. 依 v1 的 E-4 找到上次確認過的版面。
2. 用現在的視窗大小重新排一次。
3. 結果和上次是「同一個版面」：直接恢復，不需要確認。
4. 不是：顯示**規則安全畫面**（空的工作區加固定答案區），同時產生一個提案「恢復上次的內容（版面已調整）」，你按「套用」才生效。沒按之前，磁碟上的指標不變。
5. 連一個合格的排法都找不到：只顯示規則安全畫面，記 `restore_unfit`，不產生提案。

**N-3 回滾目標不合格**：要回滾時，上一版在現在的視窗大小下已經不合格，就改成規則安全畫面，記 `rollback_target_invalid`，那一筆的復原按鈕停用。之後可以接受新提案。

**N-4 固定案例**：同螢幕重啟；螢幕變小、分列改變；必要元件放不下；寫入很慢時視窗大小改變；上一版也不合格。每一案都不得自動啟用沒有確認過的版面。
