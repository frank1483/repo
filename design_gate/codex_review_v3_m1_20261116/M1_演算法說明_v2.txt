## 1. Domain Gate
Gate 把一句中文輸入分成 7 種結果之一：問答、UI 操作、告警相關、任務規劃、報告、飛控指令（HOLD）、領域外。M1 只做第一段規則，不排隊、不用模型；embedding 與模型選類別是 M2 的事。
- 
輸入：使用者文字（上限 200 字，超過就截斷並記錄）、詞庫版本。
- 
輸出：{class, source:\"rule\", scores, matched_terms, lexicon_version}。
步驟：
- 
正規化：全形轉半形、英文轉小寫、去除多餘空白。
- 
飛控指令先判：命中「飛控動詞」詞庫（起飛、降落、返航、解鎖、拍照等）且是命令句（不是「怎麼」「為什麼」這類問句），就回 HOLD，沿用既有 safety_hold。問句不算指令，例如「返航點在哪」是問答。
- 
類別打分：每類一組關鍵詞，每個詞有權重 1 或 2。一類的分數是命中詞的權重加總，用字串比對，不分詞。
- 
領域外：所有類別都 0 分，而且沒有命中任何領域詞（domains/*.json），就回固定的拒答。「查不到資料」不算領域外，會走到工具再說查不到。
- 
決定：最高分 ≥ T（先用 2），而且比第二高多至少 1 分，就是那一類。否則 CLARIFY，列出分數最高的兩類讓使用者選。
複雜度：詞庫上限 500 詞，每句最多比對 500 次，在 GUI 執行緒上也不會卡住告警。T 與「多 1 分」只是起始值，會先用校準包調，再凍結後跑正式驗收包（F-12）。

【v2 改】T3 是問答用的分析，不取代告警。既有 JS 版告警不支援 x500 多旋翼，所以桌面以 Python 告警引擎為準，APK 以新移植的 P1 多旋翼版為準；T3 和告警不一致時，答案要同時列出告警結果。電量斜率是新寫的演算法（既有 energy.py 沒有這個函式），完整公式、最少樣本數、缺值與亂序的處理會寫成契約附件。ε 與 60 秒視窗會用校準包定。每個工具都有 Python 對照版做 golden 比對（G4）。

## 4. 事實句與證據
【v2 改】答案由「句型模板＋事實」組成，每一句都能由程式檢查。程式先把這次請求所有合法的句子做成候選（claim），每個候選已經綁好事實、時間區間、機體、比較基準與措辭強度，並有一個編號。M1 的規則版依固定順序全部採用；M2 的模型只能回傳要用哪些編號，不能寫任何文字或數字（F-05）。
Fact：{fact_id, kind, subject, value, unit, time, source}。kind 只有 value、trend、threshold、count、series、doc_quote、not_found 七種。
| 
模板 | 
句型 | 
槽位要求 | 
| 
T-VALUE | 
「{subject} 目前是 {value}{unit}（{time}）」 | 
1 個 value 事實 | 
| 
T-TREND | 
「{subject} 在最近 {window} 內{trend}」 | 
1 個 trend 事實 | 
| 
T-THRESH | 
「{subject} {高於／低於} 門檻 {threshold}{unit}」 | 
1 個 threshold 事實，比較方向由程式算 | 
| 
T-COUNT | 
「{時段} 內有 {n} 筆 {等級} 告警」 | 
1 個 count 事實 | 
| 
T-ETA | 
「照目前趨勢，約 {value} 分鐘後到保留電量」 | 
1 個 trend 事實＋它的剩餘時間 | 
| 
T-DOC | 
手冊原文片段＋出處（文件、標題、版本），不轉述 | 
1 個 doc_quote 事實 | 
| 
T-NOTFOUND | 
「查不到 {subject} 的資料」 | 
1 個 not_found 事實 | 
【v2 改】檢查規則：選到的編號要在這次請求的候選裡；槽位型別要對上；單位要跟事實一致；事實的機體、任務、紀錄版本與時間要屬於這次請求；不能出現候選以外的文字或數字。任一項不符，整份答案退回規則模板並標「規則」；規則模板也組不出來就回「查不到」。因果句（「因為…所以…」）v1 不提供模板，所以程式不會說出沒有根據的因果。
證據編號（D-17）：E1、E2… 依答案中第一次出現的順序編，只在這一個答案內有效。每個 E# 綁著請求 ID、資料集版本與資料時間。資料變了，舊答案會標「資料已更新」，不會拿舊 E# 去對新資料。

## 5. UiPlanner 規則版
UiPlanner 只決定工作區放哪幾種元件、哪個優先，不碰座標（D-06）。元件提供者交件前，先用 ELAN_GCP_ui 現有模組當替身。

步驟：
-

-

-

## 6. LayoutEngine
LayoutEngine 把 UiPlan 變成每個元件的位置與大小，同一個輸入一定得到同一個版面。重要性靠位置與大小表達，不加說明文字（D-25）。
- 
輸入：UiPlan、工作區大小（Qt 實際回報的可用內容區，D-18）、元件目錄裡每種元件的最小與建議尺寸。
- 
輸出：LayoutSchema {plan_id, viewport, nodes:[{id, x, y, w, h}]}，單位是格點。
步驟：
- 
工作區切成 12 欄格點，列高以 8 為單位，元件之間留 16 的間距。
- 
元件依優先分由高到低，從左上開始一列一列放：這一列剩下的寬度放不下最小寬度，就換下一列。
- 
答案卡獨佔第一列的左側，寬度至少 6 欄，所以最重要的永遠在最大、最左上的位置。
- 
用到同一個事實的元件放在相鄰位置，例如電量數值卡就放在電量趨勢圖旁。
- 
每一列放完後，剩下的寬度依優先分比例分給該列的元件。
- 
高度超出工作區：先把元件縮到最小尺寸；仍放不下，就拿掉可省略、分數最低的那個再排一次；不可省略的也放不下，就失敗，維持上一個有效畫面。
複雜度：元件最多 5 個，最多重排 5 次，計算量是幾十次加減法。永遠不碰工作區以外的告警、地圖等固定骨架（D-01）。

## 7. Validator 擴充與上畫面流程
Validator 在元件上畫面前後各檢查一次，任一項不過就保留原畫面，並記下原因。新增的規則都掛在既有 Verifier 的 extraChecks 上。
上畫面前：
- 
契約版本對得上；元件都在白名單內；元件不超過 5 個。
- 
每個元件綁的事實都屬於這次請求。
- 
位置在工作區內、彼此不重疊、不小於最小尺寸。
- 
必要標示都在：「模型／規則」來源、每個數字的單位與 E#、告警等級、「查不到」、「降級」、「重放」。
- 
沒有必要標示以外的說明文字節點（D-25）。例如「以下是電量趨勢」這類標題不加，趨勢圖放在哪、多大，就已經說明了。
上畫面後：沿用既有的超出邊界、重疊、被遮住、文字被截斷、鎖定模組被動五項檢查，再加一項「告警被遮住」（ALERT_OCCLUDED，目標 0 次）。
上畫面流程（D-15、F-04）：
- 
在看不見、不能操作的暫存區建好候選畫面。
- 
跑上面兩段檢查。
- 
【v2 改】答案文字與手冊引用直接顯示在固定的答案區。要新增圖表、表格、診斷元件，或會拿掉、取代工作區裡已經有的元件，就先請使用者按「套用」。已確認元件的資料值更新不用再確認。
- 
使用者確認後，再查一次版本：資料、版面跟候選建立時一樣，才一次切換。不一樣就重新產生候選。
- 
切換後可以復原。復原只回到前一個畫面，不會把遙測或告警倒回去。

## 要你確認的清單
全部同意可以直接回「照說明」，或寫「照說明，除了第 6 項…」。括號內是我的建議。
- 
Gate 的 7 種結果與起始門檻（T = 2、領先 1 分），之後用校準包調。
- 
問句不算飛控指令（例如「返航點在哪」走問答，不 HOLD）。
- 
參數不唯一時，最多列 5 個候選讓你選。
- 
遙測超過 2 秒沒更新就標「過期」。
- 
電量趨勢用最近 60 秒、R² ≥ 0.5 才給剩餘時間。
- 
手冊檢索 M1 先只做關鍵字並標「降級」，M2 加向量（這個版本不算 QA-06 完成）。
- 
中文問題查英文手冊：M1 加一份約 200 詞的中英對照表，查詢時自動補英文詞（建議加；這是 ADR 的 Q-05）。
- 
v1 的 5 種元件：答案卡、數值卡、趨勢圖、事件表、手冊引用卡。
- 
【v2 改】你提問後的答案文字與手冊引用直接顯示；要新增圖表、表格、診斷元件，或會拿掉、取代工作區既有元件時，才請你按「套用」。（v1 寫的是「只有拿掉或取代才確認」；這裡改成和 E-04 一致，若你要維持 v1 的寫法請告訴我。）
