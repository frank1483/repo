## 請你做的事

### 一、附件 v3 是否關閉了你在稽核裡提的問題

對 R3-F01～F06、F08～F10 逐項判定：**已關閉設計／部分關閉／未關閉**，並指出 v3 的哪一節、還缺什麼。R3-F07 不在 v3，只需確認 v3 沒有假裝處理它。

### 二、附件 v3 本身的錯誤

找出：自相矛盾、和候選 ADR 或已裁決事項（D、E、G、H 項）衝突、規則順序造成的反例、漏掉的終態、無法實作或無法驗收的條文。特別請看：

1. 第一部分 §A：規則 4～11 的順序有沒有反例。例如：只有一類有分數但低於門檻 T 時，會請使用者在一個有分的類別和一個 0 分的類別之間選（`genui_m1/README.md` 最後一點）。這樣合理嗎，該怎麼改。
2. 第一部分 §A-2b：用「再、並、後」單字切子句，會不會把正常的問句切壞，造成誤擋或漏擋。
3. 第一部分 §J-3：取消一律結束並重開專用 Ollama。程序群組在 Windows 與 Linux 上的做法是否寫得夠明確；「正常完成」的證據（串流 `done:true` 加連線關閉）夠不夠。
4. 第一部分 §N-1「同一個版面」的定義，會不會讓未經確認的版面被直接恢復。
5. 第二部分 §K-4 排版步驟：有沒有不確定的地方（同分、取整、重排起點）；步驟 4 把剩餘寬度全給第一個元件，會不會讓必要元件小於最小尺寸或產生不合理版面。
6. 第二部分 §I-3：`OVERRUN_FROZEN` 期間告警區是否仍保證不受影響；恢復條件有沒有活鎖。
7. 第二部分 §L-1：四條時間軸是否真的沒有「模型之後才算向量」；§L-4 的合格片段定義會不會讓關鍵字誤命中的片段過關。
8. 第二部分 §M-1：更新租約有沒有新舊混用的空隙。

### 三、程式是否照契約寫

逐檔對照契約，找出程式和契約不一致、或契約沒寫但程式自己決定的地方。請特別看：

- `GenuiGate.js` 的 11 條規則與 v3 §A-2 是否逐條一致；詞庫（特別是把 `FLIGHT_VERBS` 也算成領域證據、名詞例外多了四個參數名稱）是否妥當。
- `GenuiTools.js` 的 `energyTrend` 與 v1 §C＋v3 §C 是否逐步一致（清理 → 亂序比例 → 排序去重 → 取視窗 → 充分性 → 零變異 → 直線 → 方向 → ETA）。注意：程式把「過期」檢查放在充分性之前、把 `reserve_pct = 100` 視為無效、Σ(x−x̄)²=0 回 INSUFFICIENT。
