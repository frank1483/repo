# v6 installation into a disposable UI copy

Run `bash ui_agent/install_into_ui.sh --check <fresh-UI-copy>` first. It verifies the text-only payload manifest after CRLF-to-LF normalization, stages all six patches sequentially, copies all twelve Agent files, checks CMake membership and the singleton, then retains the stage and patch logs. Only the 44 declared patch targets in the disposable stage are normalized to LF. Target GCP and its development handoff are unchanged in check mode; a new staging directory is created. To install, omit `--check` on that same still-uninstalled copy. Existing Agent directories and symlinks are refused. Do not run against the original UI.

Installation preserves the original GCP directory and handoff in a unique `.ui-agent-install.*` directory. Ordinary errors and handled signals during commit attempt restoration, retaining failed outputs. SIGKILL, power loss, concurrent editors and filesystem failures are not crash-atomic guarantees. Do not steal an existing `.ui-agent-install.lock`; inspect the retained paths and owner first. No old backup is deleted. Do not run an application from this copy during installation.

The CMake patch lists all twelve files, including Catalog, Host, Loop, ReadableSession, Snapshot and Verifier. The shell binds `readableViewport: root` and `readableGoalPolicy: root.agentReadableGoalPolicy`. The latter defaults to null: trusted UI integration must explicitly supply `{kind:"readable", minWidth:..., minHeight:..., allowMove:..., allowShrink:..., allowNavigate:...}` from local reviewed configuration. Width/height are QML scene units and the permissions are booleans. They are not model, environment or settings output. No legibility threshold or permission is invented by this installer. A missing policy keeps the goal path rejected before mutation; the normal confirmation, remeasurement, owned transaction and rollback checks still apply. Supplying a policy is not human_approved or training_release.

`QT_PREFIX=<existing-local-Qt> bash ui_agent/ubuntu_build_demo.sh <source-UI> <nonexistent-separate-copy>` creates a fresh local copy, installs and configures a new build-agent-v6 directory. It refuses existing or nested destinations, does not change source Git/worktree metadata, and requests offline FetchContent/CPM dependencies. It fails rather than fetching missing dependencies through those systems; arbitrary upstream CMake commands are outside that guarantee. Review upstream build behavior before a real build. The script never starts UI, Ollama, SITL or a device. CMake/Qt/native build and shell behavior remain pending Claude's first execution.

The new `test/run_install_v6_controls.py` uses a captured UI fixture and disposable copies. It is an engineering installer check, not a model or research regression suite. First-run instructions and package hashes are supplied separately. Model repair feedback, final text regression and old Qt harness waits remain for the next part7 batch.

## Installer control evidence filesystem

Place the fixture and the new evidence directory on a local Linux filesystem supporting symbolic links and directory rename (for example local ext4). Do not place evidence on a network mount without symlink support. Before running the eight controls, create a disposable symlink probe next to the intended evidence directory with Python os.symlink, and verify that it is a symlink. If that raises OSError (including errno 38) or is not a symlink, record ENVIRONMENT_UNSUPPORTED with the exception/errno and filesystem path, stop before the control suite, and choose a supported local directory. This is not an installer FAIL or a PASS; the suite has not run. Retain the original part7 3/8 and separate diagnostic 8/8 unchanged. The control program itself is unchanged in part7b.
