# Readability Overlay — first bridge

Trusted shell integration must explicitly bind `readableViewport` to the same common viewport used for measurements and set `readableGoalPolicy` with `kind: "readable"`, positive finite `minWidth`/`minHeight`, and all three boolean permissions `allowMove`, `allowShrink`, `allowNavigate`. No defaults are supplied. These properties are host policy, never model output, environment, or artificial approval fields.

The narrow `Loop.goalTemplate` phrase is intercepted before ordinary analysis or model requests. Main-map ambiguity asks for clarification. Missing policy/viewport or unsupported geometry rejects the goal without falling through to legacy scale execution or a backend. The existing actual confirmation Text displays the prepared summary, minimum dimensions and permissions; Yes consumes the card, remeasures the full basis, then creates a session. No, stale geometry/policy, page change, or double Yes cannot start another action.

The first session uses the original State owned-group token, fresh Host captures with all registered visible same-page obstacles across containers, and `Core.layoutTarget`. It dispatches the initial miniView scale only. After dispatch a Qt Timer polls every 16 ms until two consecutive complete captures agree, with a 2500 ms per-step deadline and 12000 ms session budget. Each Loop step, logical goal, and final goal is independently remeasured and verified. Frame/viewport/location/policy changes or external State revisions abort. Success creates one atomic undo entry; verification failure has no propose port and rolls back with `REPAIR_UNAVAILABLE`.

Cancel, panel close and destruction cancel the owned session and pending poll. Late callbacks are inert. A foreign group is never rolled back; rollback failure is reported distinctly and cannot be represented as successful restoration. The bridge does not run a model repair or navigation repair, even when host policy would permit those candidates. The card explicitly discloses that repair is not connected.

The new harness uses condition waits; it does not retroactively fix old harnesses. Real Qt first execution is pending. Only registered-item geometry/AABB coverage is represented: no proof of actual text legibility, popup/native video visibility, unregistered occlusion, QGC integration, board behavior, or flight readiness.
