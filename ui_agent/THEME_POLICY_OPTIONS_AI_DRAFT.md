# 色相距離與相對幅度：AI 草案，待使用者勾選

回覆 CLAUDE-APP-0389。下列為程式接口可實作的候選值與工程理由，沒有任何一項已獲使用者批准。不得讀本文件自動產生runtime policy、不得寫進預設值、人審或training_release。這不是感知辨識實驗或安全認證；本輪不呼叫模型、不執行使用者研究。

## 狀態近色最小色相距離

定義：HSL環形色相距離，0–180度。先比較使用者主色與來源紅／黃／綠一般狀態及GPS狀態色，搜尋後再對量化RGB重檢。無彩色無色相，另靠對比與圖示/文字語意。此數值不能保證不同亮度/飽和度/色覺條件下不混淆。

請使用者選一項；未選維持必填、功能不啟用：

- [ ] 15度：較多保留使用者原色；留給狀態色的禁用範圍較小，需更多實際近色視覺覆核。
- [ ] 20度（AI建議起點）：比15度擴大分離區，仍保留部分橙/青等可提案色域。本批僅將20作合成控制，紅色請求可被推到橙色附近，正好說明它不是感知安全保證。
- [ ] 30度：禁用範圍更大，更多主色請求會被移色或無解；適合使用者願意犧牲更多原色保真時評估。

理由：這是保真與排除色域的可觀察工程取捨，並無已完成實驗可證明20最優。原主色約188度，最近的紅黃綠GPS色與之仍相隔約37度，三候選都可容納原cyan。若增加被比較色群，要重算可行域，不能只套同一理由。

目前草案比較來源token為statusSuccess/statusWarning/statusCritical/gpsNone/gpsWeak/gpsGood。gpsFixed與statusInfo本來就是主色cyan，仍逐項固定不改；把它們納入主色排斥將使原主色本身衝突，故「保護不改」與「紅黃綠排斥參考」在接口中分開。其他telemetry/告警token都不改，但是否擴大排斥參考群仍需主端政策明示，不能由模型臨時更改。

## 相對調整幅度

先沿前批已交付數學定義：亮/暗是HSL lightness加減；暖/冷是R增加且B減少，或反向，G保持。這是有界通道偏移，不是色溫或等感知差模型。所有結果都須再做狀態近色/對比檢查，確認卡顯示實際色；無解保留原配置。

請使用者選一項；未選維持必填、相對請求不自填：

- [ ] 0.02：亮/暗±2個百分點；暖/冷約±5個RGB byte，較細步。
- [ ] 0.03（AI建議起點）：亮/暗±3個百分點；暖/冷約±8個RGB byte，在可見小幅調整與多次操作之間取工程折衷。
- [ ] 0.05：亮/暗±5個百分點；暖/冷約±13個RGB byte，較明顯但較容易碰到色域截斷或需要對比修正。

理由：使用者用「一點」時不宜默認大跳色；0.03是可説明的小步候選，尚無操作員實測支持其優越性。接近0/1的通道會截斷，對比修正可能大於原請求步長，必須以確認卡的實際色為準。
