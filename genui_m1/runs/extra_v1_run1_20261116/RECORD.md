## 不過的 1 案：程式和你已確認的條文不一致

- 案例：保留電量 = 100。
- 條文（附件 v3 第一部分 §C）：保留值「不是有限數字或不在 0～100」才標無效。100 在範圍內。
- 程式（`GenuiTools.js`）：把 `>= 100` 當成無效。這是我照候選 ADR 的寫法 `[0,100)` 寫的，沒有照條文。Python 對照版也是同一個寫法，所以先前兩邊比對一致並沒有抓到。
- 實際影響很小：保留值 100 時，不管標不標無效都不會算剩餘時間，差別只在多一個「保留值無效」標記。
- 處置（還沒做）：條文是你確認過的，以條文為準，程式與 Python 對照版在下一版一起改；另開新 run。

## 過了但值得記下的 3 個現象（都是條文字面的結果，不是程式錯）

1. 「返航後電量會剩多少」被擋成飛控指令。原因是用「後」切句，前半「返航」沒有問句標記。方向是保守的（誤擋，不是漏擋）。
2. 「高度多少」要使用者在「問答」和一個 0 分的類別之間二選一（Gate 校準基準線的同一個問題）。
3. 同時「過期」又「樣本不足」時，程式先回過期。條文沒有寫先後，要補一句。

這三點會寫進 Gate／電量條文的修正版，請 Codex 看過後再給你確認。
